# DisplayFlip 설계

날짜: 2026-10-02

## 목표

M4 맥과 Windows PC에서 버튼 또는 단축키 한 번으로 모니터 두 대를 지정된 입력으로 전환한다.

앱 이름: DisplayFlip  
식별자: `com.displayflip.app`

## 사용 환경

- 컴퓨터: M4 맥 1대, Windows PC 1대. 두 대 모두 같은 앱을 설치한다.
- 모니터: 주연테크 Q27C15 2대.
- 연결:
  - 모니터 1: 맥 HDMI, Windows DP
  - 모니터 2: 맥 DP, Windows HDMI
- 맥은 오리코 TB4 12-in-1 썬더볼트4 독을 사용한다.
- 독의 칩셋, 두 화면의 실제 연결 경로, DDC/CI 전달 여부는 확인되지 않았다. 상품명으로 호환성을 단정하지 않는다.

## 전환 명령

목적지를 명시하는 두 명령을 제공한다. 현재 입력을 읽어 뒤집는 토글은 만들지 않는다. 현재 입력을 읽지 못해도 전환 명령은 보낼 수 있어야 한다.

| 명령 | 모니터 1 | 모니터 2 |
|---|---|---|
| 맥으로 | 그 모니터의 HDMI 번호 | 그 모니터의 DP 번호 |
| Windows로 | 그 모니터의 DP 번호 | 그 모니터의 HDMI 번호 |

이 대응은 고정 규칙이다. 설정으로 바꾸지 않는다.

어느 PC에서든 두 명령을 모두 실행할 수 있다. 화면을 출력 중이지 않은 연결로는 DDC/CI가 전달되지 않을 수 있고, 그때 해당 모니터는 실패한다. 두 화면이 물리적으로 동시에 바뀐다고 보장하지 않는다. 번호는 모니터 1, 모니터 2 순서로 보낸다.

## 기술

- 데스크톱 앱: Tauri 2
- 화면: TypeScript + React. 현재 Vanilla TypeScript 화면은 구현 시 React로 교체한다.
- 전환 판단, 설정 저장, 단축키, 자동 실행: Rust
- Windows 제어: 물리 모니터 열거, `GetVCPFeatureAndVCPFeatureReply`, `SetVCPFeature`. 입력 선택 기능 번호는 `0x60`이다.
- macOS 제어: 같은 제어 모듈 인터페이스를 구현한다. M4에서 m1ddc로 시험 전환이 되는지 확인하기 전에는 DDC를 시도하지 않고 미확인을 반환한다. 확인 결과에 따라 그 모듈만 외부 실행 도구 또는 Swift 구현으로 교체한다.

## 구성

| 부분 | 하는 일 | 의존 |
|---|---|---|
| 화면 (React) | 맥으로, Windows로 버튼, 설정, 트레이 메뉴 | Tauri 명령만 호출 |
| 앱 명령 (Rust) | 전환, 모니터 목록, 시험 전환, 설정 저장, 단축키, 자동 실행 | 도메인, 설정, 제어 모듈 |
| 도메인 (Rust) | 목적지에 따라 각 모니터에 보낼 번호를 계산 | 없음 |
| 설정 (Rust) | 이 PC의 설정을 파일로 저장 | 없음 |
| 제어 모듈 (Rust) | 모니터 목록, 입력 번호 전송, 가능하면 현재 번호 읽기 | Windows API 또는 macOS 구현 |

화면과 설정 형식은 운영체제를 모른다. 제어 모듈은 다음만 제공한다.

- 모니터 목록: 안정 식별자와 사람이 읽는 이름
- 입력 번호 전송
- 현재 입력 번호 읽기. 읽기는 실패할 수 있다.

## 설정

각 PC는 자신의 설정 파일만 가진다. 맥과 Windows는 설정을 주고받지 않는다. 파일은 앱 설정 디렉터리의 `settings.json`이다.

저장 예:

```json
{
  "monitors": {
    "1": { "id": "GSM5B00-12345", "hdmiCode": 17, "dpCode": 15 },
    "2": { "id": "GSM5B00-67890", "hdmiCode": 17, "dpCode": 15 }
  },
  "hotkeys": { "toMac": "Ctrl+Alt+M", "toWindows": "Ctrl+Alt+W" },
  "launchAtLogin": true
}
```

빠진 역할, 식별자, 번호는 미설정이다. 예시의 식별자와 번호는 형식만 보여 주며, Q27C15의 실제 값이 아니다.

저장하는 값:

- **모니터 역할.** 모니터 1과 모니터 2에 감지된 모니터의 안정 식별자를 하나씩 연결한다. 두 역할은 서로 다른 모니터여야 한다. Windows에서는 EDID의 제조사, 제품, 시리얼을 우선하고, 시리얼이 없으면 장치 인스턴스 경로를 쓴다. 화면에는 모델명도 같이 보여 준다.
- **입력 번호.** 모니터마다 HDMI 번호와 DP 번호를 저장한다. 값은 0 이상 255 이하의 정수이며, VCP `0x60`에 쓰는 번호다.
- **단축키.** 맥으로, Windows로 각 하나. 기본값은 `Ctrl+Alt+M`, `Ctrl+Alt+W`이다. 설정에서 바꿀 수 있다. macOS에서도 같은 키 조합을 등록한다.
- **로그인 시 실행.** 기본값은 켜짐이다. 설정에서 끌 수 있다.

## 화면 흐름

UI 문구는 한국어로 둔다.

설정이 완료되지 않은 상태로 실행되면 설정 창이 열린다. 설정이 완료된 뒤 로그인으로 실행되면 창을 열지 않고 트레이 또는 메뉴 막대에만 둔다. 사용자는 감지된 모니터를 두 역할에 연결하고, 번호를 하나 넣어 그 모니터만 시험 전환한다. 화면이 해당 단자로 바뀌면 그 번호를 HDMI 또는 DP로 저장한다. 현재 번호를 읽을 수 있으면 시험 전에 보여 준다. 읽기에 실패해도 시험 전환과 저장은 가능하다. 시험 전환은 전체 설정이 끝나기 전에도 고른 모니터 하나에 대해 동작한다.

두 역할, 각 모니터의 HDMI 번호와 DP 번호, 현재 연결된 두 모니터가 모두 있을 때만 맥으로와 Windows로가 번호를 보낸다. 하나라도 없으면 어느 모니터에도 번호를 보내지 않고, 빠진 항목을 알려 준다. 버튼은 이때도 누를 수 있다.

창의 버튼, 전역 단축키, 트레이 메뉴는 같은 두 명령을 실행한다. 창을 닫으면 프로세스는 트레이 또는 메뉴 막대에 남는다. 트레이 메뉴는 맥으로, Windows로, 열기, 종료를 제공한다. 로그인하면 앱이 자동 실행된다.

## 오류

전환 결과는 모니터마다 다음 중 하나다.

- **전달됨.** 전송이 성공했고, 읽은 번호가 보낸 번호와 같다.
- **전달됐으나 확인 불가.** 명령은 받아졌지만 현재 번호를 읽지 못했다. 읽기 실패만으로 전환 실패로 처리하지 않는다.
- **실패.** 모니터를 열지 못했거나 명령이 거부된 경우다. 전송 자체가 실패하면 현재 번호를 읽지 않는다. 전송이 성공한 뒤에만 읽기를 시도하고, 읽은 번호가 보낸 번호와 다르면 역시 실패다. 운영체제가 준 이유 또는 번호 불일치를 같이 보여 준다.

한 대만 실패해도 다른 대의 결과를 되돌리지 않는다. 전환이 진행 중이면 새 명령은 보내지 않고 이미 전환 중이라고 알려 준다. 이 잠금은 프로세스 메모리에만 있고 설정에 저장하지 않는다.

창이 열려 있으면 결과를 창에 보여 준다. 창이 숨겨져 있으면 같은 내용을 알림으로 보여 준다. 단축키 등록에 실패하면 그 사실을 알려 주고 버튼 전환은 계속 동작한다. 로그인 자동 실행 등록에 실패하면 그 설정은 켜지지 않은 채로 남고 앱 실행은 계속된다.

macOS 제어 모듈은 검증 전에 미확인 실패를 반환한다. 문구는 "이 Mac에서는 모니터 제어가 아직 확인되지 않았습니다."로 고정한다.

## 테스트

자동 테스트는 실제 모니터 없이 도메인, 설정, 가짜 제어 모듈만 검사한다.

- 맥으로는 모니터 1에 HDMI 번호, 모니터 2에 DP 번호를 고른다. Windows로는 그 반대다.
- 역할, 번호, 연결된 모니터 중 하나라도 없으면 명령을 만들지 않는다.
- 두 역할에 같은 모니터를 넣을 수 없다.
- 전환이 진행 중이면 새 명령을 만들지 않는다.
- 설정 파일을 저장한 뒤 다시 읽으면 모니터 식별자, 번호, 단축키, 로그인 실행 값이 유지된다.
- 가짜 제어 모듈로 성공, 명령 거부, 현재 번호 읽기 실패, 읽은 번호 불일치를 넣어 세 가지 결과가 나오는지 확인한다.

실제 모니터와 독은 자동 테스트에 넣지 않는다. Windows에서 손으로 확인할 항목:

- 모니터 두 대가 목록에 나오고, 역할과 번호를 저장한 설정이 재실행 뒤에도 유지된다.
- 시험 전환으로 HDMI와 DP 번호를 저장할 수 있다.
- 설정이 끝난 뒤 맥으로와 Windows로가 두 모니터에 지정된 번호를 보낸다.
- 창을 닫아도 단축키와 트레이 메뉴가 동작하고, 다시 로그인하면 앱이 실행된다.
- 화면을 가지고 있지 않은 PC에서 명령을 보내면 실패 이유가 모니터별로 보인다.

macOS 구현 전에 M4에서 m1ddc로 같은 시험 전환이 되는지 확인한다. 그때 외부 도구를 유지할지 Swift 모듈로 갈지를 정한다. 그 전에는 macOS 제어 모듈이 미확인을 반환하는지만 검사한다.
